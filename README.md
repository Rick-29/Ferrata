# Swissquote Wallet (Ferrata)

A bank-grade self-custody wallet: a passkey smart account where every transaction is
risk-scored, **co-signed by Swissquote**, written to a hash-chained audit log with
Swissquote-signed receipts, and recoverable through a timelocked, cancellable flow.
Swissquote can refuse to co-sign but can never move funds.

Three people, three layers:

## Run

```sh
cd backend
cargo run -p sq-services                 # http://localhost:8787, loads ../fixtures
cargo test --workspace                   # also regenerates frontend/packages/types/src
cargo clippy --workspace --all-targets -- -D warnings
wasm-pack build wallet-wasm --target web --release --out-dir ../../frontend/packages/core-wasm
```

Environment (all optional): `SQ_PORT` (8787), `SQ_FIXTURES_DIR` (`../fixtures`),
`SQ_SIGNING_SEED` (32-byte hex; random per start if unset, printed in the log),
`SQ_LOG_SNAPSHOT` (JSON file mirroring the audit logs), `SQ_DEV_SIGNER` (`1` by default;
`0` disables the mock passkeys under `/dev`).

## The demo flow in six calls

Everything the UI needs, in order. Hashes and amounts are `0x` hex strings; `u64`s are JSON numbers.

```text
1. POST /auth/session        { username: "alice", password: "demo" }        → Session
2. GET  /ownership/challenge                                                 → { challenge }
   POST /wallet/register     { owner, challenge, signature }                 → { address, account }   (creates the chain account)
3. POST /chain/faucet        { address, asset: USDC|null, amount }           → SubmitResult
4. POST /assess              { tx, account? }                                → { action, assessment, signals, prepared: { user_op_hash, nonce }, next_seq, head }
5. POST /cosign              { tx, user_op_hash, seq, prev_head, step_up, account? }
                                                                             → { kind: "cosigned", entry, cosignature }
                                                                             | { kind: "step_up", entry }          → retry with step_up: true
                                                                             | { kind: "held", entry, hold_id }    → POST /holds/{id}/justify { text } → HoldState { cosignature, release_entry }
                                                                             | { kind: "refused", entry }
6. POST /chain/submit        { tx, nonce, owner_signature, cosignature }     → { tx_hash, block_number, kind }
```

The owner signs `user_op_hash` with the passkey. Two signature shapes are accepted:
`{ kind: "ed25519", signature }` (fast fake passkey, e.g. `@noble/ed25519` in the popup) and
`{ kind: "webauthn", authenticator_data, client_data_json, signature }` straight from
`navigator.credentials.get` with `challenge = user_op_hash` bytes. The chain verifies both.

**Mock passkeys while WebAuthn is not wired:** `POST /dev/passkeys { name }` returns an
owner key and address; `POST /dev/passkeys/{name}/sign { hash }` returns an owner signature.
Deterministic per name, in-memory only, labelled dev.

### Demo addresses (from `fixtures/`)

| Send USDC to | Band | Why |
| --- | --- | --- |
| an address in `account.known_recipients` | Low | nothing fires |
| any new address, small amount | Low | `NEW_RECIPIENT` (20) |
| any new address, more than 1000 USDC | Medium → step-up | `LARGE_AMOUNT` + `NEW_RECIPIENT` (45) |
| `0x…c0ffee` | High → hold | 2 hops from the mock mixer (`MIXER_EXPOSURE` 40 + 20) |
| `0x…dead` | Critical → refused | sanctions list (100) |
| unlimited `approve` from an unknown origin | High | `UNLIMITED_APPROVAL` 30 + `UNKNOWN_ORIGIN` 10 + 20 |

USDC is `0xaaaa…aaaa` (6 decimals). ERC-20 calldata is the standard `transfer(address,uint256)` encoding.

## Full endpoint list

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/auth/session` | mock login (`fixtures/accounts.json`) |
| GET | `/ownership/challenge` | FINMA-style ownership challenge, 5 min TTL |
| POST | `/wallet/register` | verify passkey signature over challenge, create chain account |
| POST | `/assess` | decode + simulate + signals + score; includes `prepared` and log position |
| POST | `/cosign` | server re-scores, checks `seq`/`prev_head`, signs receipt, returns outcome |
| GET | `/holds/{id}` · POST `/holds/{id}/justify` | hold review (mock compliance: ≥10 chars, no "fraud"/"urgent") |
| GET | `/log/{address}` | audit log with receipts, `head`, `next_seq` |
| POST | `/recovery/start` | new owner key + KYC script (`kyc-pass` / `kyc-fail`) → timelock |
| GET | `/recovery/{id}` · POST `/recovery/{id}/cancel` · POST `/recovery/{id}/execute` | cancel needs the current owner's signature over `cancel_hash`; execute rotates the owner on-chain |
| POST | `/reconcile/{address}` | chain-vs-log diff; escape-hatch exits and unlogged co-signed txs are Critical |
| GET | `/chain/info` | chain id, tokens, Swissquote public key |
| POST | `/chain/accounts` · GET `/chain/accounts/{address}` | create / read account (balances, nonce, escape status) |
| POST | `/chain/faucet` | credit any address |
| POST | `/chain/prepare` · POST `/chain/simulate` | `user_op_hash` + nonce / balance deltas |
| POST | `/chain/submit` | validates owner sig + co-signature (or unlocked escape hatch), mines one block |
| POST | `/chain/escape/hash` · `/chain/escape/start` · `/chain/escape/cancel` | 14-day timer, 120 s in the demo |
| GET | `/chain/history/{address}` · `/chain/blocks/{n}` · `/chain/tx/{hash}` | explorer reads |
| POST | `/dev/passkeys` · GET `/dev/passkeys` · POST `/dev/passkeys/{name}/sign` | mock passkeys (dev only) |

Errors are always `{ code, message, details }` with a matching status. Codes: `CORE_*`
(decode, `SEQ_GAP`, `CHAIN_BROKEN`, `BAD_RECEIPT`), `CHAIN_*` (`BAD_NONCE`,
`BAD_OWNER_SIGNATURE`, `BAD_COSIGNATURE`, `ESCAPE_LOCKED`, `INSUFFICIENT_BALANCE`, …),
`NOT_FOUND`, `UNAUTHORIZED`, `CONFLICT`, `BAD_REQUEST`. Held and refused are 200s, not errors.

## Pseudo-blockchain rules

- An account is 2-of-2: owner passkey + Swissquote's Ed25519 key, fixed at creation.
- Address = last 20 bytes of `keccak(owner key)`. One block per transaction, instant.
- `user_op_hash = keccak("SQW-USEROP-v1" ‖ chain_id ‖ from ‖ to ‖ value ‖ keccak(data) ‖ nonce)`.
- Co-signature = Ed25519 over `"SQW-COSIGN-v1" ‖ user_op_hash`.
- Escape hatch: owner-only start, timelock, then transfers only to the declared exit address, no Swissquote. Shows up in reconciliation as Critical.
- Owner rotation (recovery) needs only Swissquote's co-signature, after the service-side timelock.


## Rules of the house

- No private key, share or seed appears in any Rust parameter, field or log line (the `/dev` keyring is the labelled exception, off with `SQ_DEV_SIGNER=0`).
- `wallet-core` is pure. Time and external signals are passed in.
- No `unwrap` / `expect` / `panic!` outside tests; workspace lints deny them.
- Hold and refuse are `Ok(outcome)`, never `Err`.
- Only established crypto crates: `sha2`, `ed25519-dalek`, `p256`, `alloy-primitives` (keccak).
