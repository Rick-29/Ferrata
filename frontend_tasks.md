# Frontend and middleware tasks

Everything the extension side (P2 UI, P3 middleware) has to do to reach the testnet goal in
`testnet_plan.md`. The backend contract referenced here is the one after backend task B1
(no hold; warn + accept + second signature; regulatory refusal only). Types come from
`frontend/packages/types/src`, regenerated by `cargo test` in `backend/`.

Server: `http://localhost:8787`. Every non-public call carries `Authorization: Bearer <token>`.
Public: `/auth/session`, `/chains`, `/networks`, `/model`, `/chain/*`, `/dev/*`.

## 1. SDK package (`frontend/packages/sdk`) — P3

`HttpSwissquoteApi`: one method per endpoint, typed with the generated DTOs, every failure mapped
to `SdkError { code, source, message }` where `code` is the backend's `ApiError.code` (`SQ_` prefix
in the UI table). No retries on writes.

| Method | Endpoint | Notes |
| --- | --- | --- |
| `login` | `POST /auth/session` | keep the token in the background only |
| `challenge` / `register` | `GET /ownership/challenge`, `POST /wallet/register` | `owner` is the passkey public key (`{ kind: "p256", key }`) |
| `overview` | `POST /wallet/overview { owner }` | one account per registered chain |
| `assess` | `POST /assess { tx, account? }` | returns `intent_id`, `prepared.user_op_hash`, `next_seq`, `head` |
| `cosign` | `POST /cosign { tx, user_op_hash, seq, prev_head, step_up?, accepted_risk, account? }` | see §4 |
| `cancelIntent` | `POST /intents/{address}/{id}/cancel` | when the user denies |
| `submit` | `POST /chain/submit { tx, nonce, owner_signature, cosignature }` | Ferra chain only |
| `log` / `history` | `GET /log/{address}`, `GET /chain/history/{address}` | Activity screen |
| `settings` | `GET /settings/{address}`, `POST /settings/{address}/hash`, `POST /settings/{address}` | owner-signed |
| `linkAddress` | `POST /wallet/addresses` (backend B2) | after creating network keys |
| `ingest` | `POST /chain/ingest` with `linked` (backend B4) | after a real broadcast |
| `sync` | `POST /chain/sync` | once after a broadcast; the server loop does the rest |
| `assessExternal` | `POST /assess/external` (backend B6) | Solana / opaque transactions |

Local audit log: keep the `SignedEntry` list per address in `chrome.storage` and append what
`/cosign` returns; `next_seq` and `head` for the next call come from it (or from `/assess`).
Later: verify receipts locally with the WASM core (`wallet-wasm`), not required for the demo.

## 2. Background worker (`src/background/`) — P3

- Holds the session token and the SDK; nothing else holds the token.
- Implements the real `UiBridge` behind `chrome.runtime` messages from popup and approval window.
- Holds the **network keys** (§3) and performs every signature that is not a passkey signature.
- Opens the **approval window** on dApp requests (§5) and resolves the dApp's promise with the result.
- Refuses to sign or broadcast anything that has no Swissquote co-signature and receipt.

## 3. Keys — P3

| Key | Where | Used for |
| --- | --- | --- |
| Passkey (P-256, WebAuthn) | the authenticator; public key registered as `OwnerKey::P256` | Ferra account owner; signs `user_op_hash`, `step_up_hash`, settings hash, recovery cancel |
| EVM key (secp256k1, `viem` `privateKeyToAccount`) | background, encrypted in `chrome.storage` | Sepolia transactions |
| Solana key (Ed25519, `@solana/web3.js` `Keypair`) | background, encrypted in `chrome.storage` | devnet / pump.fun transactions |

Encrypt with a key wrapped by the passkey PRF extension when available, else a device key in
storage for the demo (say so in the UI). Never log, never render, never send. Register each
address with `POST /wallet/addresses` so the backend sync loop and the visualiser know them.

Until WebAuthn is wired: `POST /dev/passkeys { name }` and `POST /dev/passkeys/{name}/sign { hash }`
give an Ed25519 owner the backend accepts (`{ kind: "ed25519", … }`).

## 4. The send / approve flow against the real backend — P3 + P2

```text
1. assess   POST /assess                     → { intent_id, assessment, prepared, next_seq, head }
2. show     ConfirmScreen (review phase)
3. deny     POST /intents/{addr}/{id}/cancel → done (intent_outcome: cancelled)
4. allow    passkey signs prepared.user_op_hash
            POST /cosign { step_up: null, accepted_risk: false }
              → { kind: "cosigned", entry, cosignature }              → go to 6
              → { kind: "step_up", entry, step_up_hash, level }        → go to 5
              → { kind: "refused", entry, reason: "regulatory" }       → OutcomePanel "refused" (no reasons shown)
5. confirm  level "standard":  passkey signs step_up_hash → POST /cosign { step_up: sig, accepted_risk: false }
            level "high_risk": user ticks "Je comprends les risques", passkey signs step_up_hash
                               → POST /cosign { step_up: sig, accepted_risk: true }
            (seq / prev_head advance by one between the two calls: every outcome is a log entry)
6. execute  Ferra chain: POST /chain/submit with the owner signature + cosignature
            real network: background signs with the network key and broadcasts, then
                          POST /chain/ingest { …, linked: { intent_id, user_op_hash } }
7. record   append `entry` (and the second one from step 5) to the local log; OutcomePanel "confirmed"
```

Map to `UiBridge`: `previewSend` = 1; `confirmSend(previewId, { stepUp, acceptedRisk })` = 4/5/6/7;
`cancelSend(previewId)` = 3 (new). `SendOutcome.confirmation_required.level` is the backend's
`level`. Add `acceptedRisk` to `confirmSend`'s options; `ConfirmScreen` already knows the value.

## 5. dApp providers — P3

- `inpage.ts` injected by `content.ts`: EIP-1193 `window.ethereum` (`eth_requestAccounts`,
  `eth_chainId` = `0xaa36a7` Sepolia, `eth_sendTransaction`, `personal_sign`, `eth_signTypedData_v4`)
  and a Solana wallet-standard wallet (`connect`, `signTransaction`, `signAndSendTransaction`,
  `signMessage`) registered via `@wallet-standard/wallet`.
- Each request → background → `POST /assess` (EVM) or `POST /assess/external` (Solana) → approval
  window → §4 → result back to the page. Denied → EIP-1193 error 4001 / wallet-standard reject.
- `manifest.ts`: `content_scripts` on `<all_urls>` (or the dApps you demo), `web_accessible_resources`
  for the inpage script, `permissions: ["storage", "notifications", "alarms"]`.
